# Steal a Ghost (Roblox)

Collect-and-defend idle tycoon with PvP theft, inspired by "Steal a Brainrot". 8-player servers (one base each), 15–60 min sessions, built for short clips. Halloween event theme.

- **Economy loop:** buy a ghost from the walkway → it flies to your base (other players can outbid you while it flies) → its income piles up on the green collect pad in front of its grave → step on the pad to collect → buy better ghosts.
- **Risk loop:** good ghosts get stolen (the owner hears an alarm). Defend your base (lock it, bonk thieves with the bat, cage them, mine the approach) or raid others.
- **Collection loop:** the Ghost Index (side menu, M) tracks every ghost you've owned; each new find pays a one-time gem reward.
- **Progression and retention:** rebirths (trade cash + base ghosts for a permanent income boost and gems), the Haunted Hour server event every 15 min (rare-ghost luck, faster spawns), a friend income boost with an Invite button, a daily gem streak, and a gem/cash Shop with an Inventory.
- `CHANGELOG.md` has a section per feature added in the autonomous session of 2026-10-16 (PRs #28–#34), with what was and wasn't tested.

The user is new to Roblox development: explain Roblox concepts briefly when they come up, and keep code readable over clever.

## Toolchain
- **Rojo** syncs `src/` into Studio (`default.project.json`). Start `rojo serve` in a Terminal tab (`run_in_terminal`, so it keeps running), then the user presses Connect in Studio's Rojo plugin; Studio reopening needs a fresh Connect. After editing, confirm the change reached Studio (`script_grep`) before playtesting: a playtest started before Rojo syncs runs old code, and edits made during a playtest only apply after restarting it.
  - If Connect brings a lot of changes, the plugin shows them and waits for the user to press **Accept**; until then nothing syncs.
  - A `rojo serve` left running for a long time (overnight) can stop picking up file changes even though it looks fine. Restart it (stop its tab, run it again) and have the user reconnect.
- **Roblox_Studio MCP** (`.mcp.json` → `%LOCALAPPDATA%\Roblox\mcp.bat`, Studio's built-in server). Use it to inspect the game tree, run Luau, playtest (`start_stop_play`, `get_console_output`, `screen_capture`), search/insert Creator Store assets, upload images, and generate meshes. The place is published (placeId 125248956556861); the Studio id changes whenever Studio reopens, so call `list_roblox_studios` again if one stops working.
- Tools live in `%USERPROFILE%\.roblox-tools\bin` (rojo, stylua, selene, wally). Rokit and Selene can't reach the internet on this machine (Rust HTTP stack fails); `scripts/install-tools-direct.ps1` re-downloads tools via PowerShell instead.
- Format with `stylua src` before finishing a change. Stylua also rewrites line endings in files you didn't touch, so check the real changes with `git diff --ignore-cr-at-eol --stat` and only `git add` the files with real changes (the rest show as modified but differ only in line endings).
- **Icons** (hotbar items, side menu, gem) are drawn in code, in one "sticker" style (thick dark outline, flat Halloween colours, white shine): `scripts/draw-*.ps1` → `assets/*.png`. Run them from the PowerShell tool (`& "E:\Claude\scripts\draw-x.ps1" -OutPath ...`); `powershell -File` is blocked by the execution policy. To upload: serve the folder (`python -I -m http.server 8765 --bind 127.0.0.1` in the background from `assets/`), call `upload_image` with `http://127.0.0.1:8765/<file>`, stop the server, and put the returned `rbxassetid://` in `GameConfig`.
- **Git:** private repo https://github.com/JermaineN/steal-a-ghost, branch `main`. Commit only when asked; push only when asked. The GitHub CLI is at `C:\Program Files\GitHub CLI\gh.exe` (not on PATH).
- **"Create a PR and merge it"** is the usual request: make a branch, commit only the files for this change, push, `gh pr create --body-file <file>` (in PowerShell 5.1, quotes inside an inline `--body` break the arguments), `gh pr merge <n> --merge --delete-branch` (it also switches back to `main` and pulls). Say in the PR what was and wasn't playtested.
- Merged changes only reach players after the user **publishes** from Studio (File → Publish to Roblox); remind them.

## Layout
- `src/shared` → ReplicatedStorage.Shared:
  - `Config/GameConfig`: all tuning numbers, asset IDs (sounds, icons) and allow-lists, including `PlotCount = 8`.
  - `Config/GhostConfig`: the ghost list and `Rarities` (order, colour, `indexGems` reward): Common … Mythic, then Divine (7) and Secret (8). Everything that lists ghosts (shop, Index) reads this, so a new ghost is one row. `divine_1` / `secret_1` are placeholders (simple ball look) the user will design; never change a live ghost's id (saves store ids).
  - `Config/ItemConfig`: Shop items (id, name, description, price, `currency` "gems"/"cash", colour, image). The 6 current items are placeholders the user will design; they don't do anything yet.
  - `Theme` (shared colours: money green, gem blue, walkway-income yellow, `RebirthPurple`, `FriendPink`, rarity text gradients `RarityGradients` for Legendary/Mythic/Divine/Secret), `Format` (`Format.cash`: 1500 → "1.50K", rolls up to the next suffix instead of "1000M"), `Remotes` (every RemoteEvent, with a comment on direction and arguments).
  - Shared maths used by both sides: `Rebirth` (cost, multiplier, `income(base, rebirths)` rounded to whole dollars, gems), `HauntedHour` (reads the event's start/end attributes on ReplicatedStorage, in `workspace:GetServerTimeNow()` time; `isActive()`), `DailyReward` (streak rules, `today()` = UTC day number).
- `src/server` → ServerScriptService.Server: `init.server.luau` starts services, sets walk speed, and owns the PlayerAdded/PlayerRemoving order.
  - `MapBuilder` builds the walkway (12 studs wide), 8 graveyard bases (`GraveyardBase`; spacing `PLOT_SPACING`, distance from the walkway `PLOT_DISTANCE`), each base's collect pads and lock bars/wall, invisible walls, and the map edge, all in code. `HalloweenDecor` adds lighting, decorations, cliffs and portals (`GhostPortal`); toggled by `GameConfig.HalloweenMap`. Its graveyard decor is placed from the map edge, so it follows the bases if they move.
  - `PlotService` plot ownership/bounds/lock state. `GhostService` ghost models, walkway shop, placed ghosts (single source of truth: `placed[player][slot]`). A bought ghost is owned and saved immediately, then flies (`flyTo`) to just in front of its base and appears on its grave; while `arriving` it can't earn, be stolen or be sold (`isInBase`), but other players can re-buy it (`tryRebuy`: price +`RepurchaseMarkup` of the original per re-buy, the outbid player is refunded). It fires `RareSpawn` for Legendary-and-rarer walkway spawns, boosts spawn luck/speed during Haunted Hour, labels base ghosts with their rebirth-boosted income, asks before selling `SellConfirmMinRarity`+ ghosts (`SellConfirm`/`SellConfirmed`, pending sale re-checked on the answer), and builds `ReplicatedStorage.GhostPreviews` (one clean copy per ghost for the Index). `GhostModels` per-ghost 3D looks and particles.
  - `StealService` carrying/delivering/returning. While carrying, the thief moves at `CarryWalkSpeed`, can't jump or hold items (`Carrying` attribute), and the owner gets `StealAlarm` on/off. `knockLoose(attacker, thief, verb)` makes a hit thief drop the ghost (used by every item). If the owner leaves mid-steal, the thief keeps the ghost (`giveToThief`, before the owner's data saves); the owner's steal message warns them. `isBeingRobbed(owner)`.
  - `ItemService` builds the hotbar items in code and checks hits on the server: **Bat** (everyone, slot 1, StarterPack), **Cage** and **Landmine** (only players in `CageAllowedUserIds` / `LandmineAllowedUserIds`, given after the bat on each spawn). Bat and cage share the swing timing and target finding (range + cone: `BatRange`/`BatHitArcDegrees`, `CageRange`/`CageHitArcDegrees`). The cage's cooldown starts only after a successful catch (`ReadyAt` attribute on the tool for the client).
  - `RagdollService` knocks players over (see Avatar joints below); `knock(player, velocity, seconds, afterLanding)`. `CageService` freezes a player in a cage (root anchored, `Caged` attribute; its caster can walk through it). `LandmineService` stores mine positions only (no parts, so only the owner's device draws them), limits/spacing/cooldown, trigger checks and the blast. `IndexService` validates Index gem claims. `LockService` lock button, see-through jail bars plus an invisible wall across the entrance (the owner passes through the wall via per-base collision groups `LockWall<n>` / `PlotOwner<n>`), and ejecting anyone inside when it locks. `EconomyService` income tick into each slot's collect pad (saved as `stored`), boosted by rebirths and the `FriendBoost` attribute; only the owner can collect, by stepping on it.
  - `RebirthService` (`Rebirth` remote; checks cost, not carrying, not being robbed; clears the base, `DataService.applyRebirth`, fires `Rebirthed` to everyone). `HauntedHourService` schedules the event by writing its times on ReplicatedStorage (no remotes). `FriendBoostService` (`FriendsHere` / `FriendBoost` attributes). `ShopService` (`ShopBuy`; price always from ItemConfig). `DailyRewardService` (`DailyClaim`; `DailyAvailable` / `DailyStreakDay` attributes; `playerLoaded` is called after data loads).
  - `DataService` DataStore load/save: `cash`, `gems`, `ghosts`, `stored`, `discovered` (Index), `claimed` (Index rewards), `rebirths`, `items` ([id] = count), `daily` ({ day, streak }). Missing keys get defaults on load. Found and claimed ghosts are mirrored to the client as `Index_<id>` / `IndexClaimed_<id>` player attributes, owned items as `Item_<id>` = count; `setGhost` marks a ghost found (every way of getting one goes through it). leaderstats has Cash, Gems and Rebirths.
  - `Util/`: `Parts` (part builder, plus `paintFullbright` for the lit-up look of the pads and lock bars without lighting their surroundings), `GhostLabel` (floating ghost name/rarity/price text), `Billboard`, `Notify` (every pop-up message goes through `Notify.send(player, message, kind, { note?, seconds? })`; `note` is a smaller line above the message).
- `src/client` → StarterPlayerScripts.Client:
  - `UI/Hud`: bottom-left cash (floating "+$/-$" to its right) and income (with "+N% friends"), the gems row above it (outlined gem icon, counts up with a floating "+N"), and the pop-up messages (`Hud.showToast(message, kind, options?)` for client-side ones). The HUD's DisplayOrder is 6, above the windows (5), so messages show over them. `UI/Sidebar`: the M / left-tab side menu; each button opens its window (opening one closes the others), with a red badge on Index while rewards wait and a "!" on Rebirth while affordable.
  - Windows: `UI/IndexPanel` (Ghost Index), `UI/RebirthPanel`, `UI/ShopPanel`, `UI/InventoryPanel`, `UI/DailyRewardPanel` (pops up on join while a reward waits, plus a reopen button). They share one look: `UI/Window.luau` builds the frame, header, close button, gradient buttons (words in their own label, since a UIGradient tints a button's text too), card grid and item pictures; use it for new windows. Each window module exposes `isOpen/open/close/toggle`.
  - `UI/SellConfirmPopup`, `UI/RareSpawnBanner` (gold banner for Legendary, the big banner for Mythic/Divine/Secret), `UI/HauntedHourHud` (countdown pill, start title, red ColorCorrection tint), `UI/InviteButton` (bottom right, next to music), `RebirthEffects` (light pillar for everyone, "REBIRTH N!" for the player).
  - `BatSwing` (swing animation for any `Swingable` tool, played on every device), `RagdollClient` (launch, physics state, standing back up on the ground), `CarryControls` (hides the hotbar and jumping while carrying or caged), `CageClient` (caster walks through their cage), `LandmineEffects` (owner-only mine visuals and everyone's explosion), `StealAlarm` (siren, music dip, pulsing red screen border).
  - `CollectEffect` (owner-only pad flash, cha-ching and cash burst on collect), `GhostPrompts` (hides Steal on own ghosts / Sell on others', and shows "Buy for $X" on others' ghosts in flight), `GhostAnimation` (bob/sway/flicker; Spectre King waddle on the walkway), `MusicPlayer` (background music through the `Music` SoundGroup, + mute button).

## Avatar joints, ragdolls and animation
- Characters use Roblox's newer avatar joints: each joint is an `AnimationConstraint` plus a `BallSocketConstraint` (no Motor6Ds). Ragdoll = turn off every AnimationConstraint except `Root` on the server (and `RequiresNeck = false`); the ball sockets take over. The hit player's own device moves their character, so the push and `Physics` state happen on their client (`Ragdoll` remote), and the push must go to every body part (with the joints off, each limb moves on its own).
- To get up, first stand the character upright on top of the ground (`PivotTo`), then restore collisions; otherwise the root part drags the body into the floor.
- Code-driven animation: change a joint's `Transform` in `RunService.Stepped` (after the Animator writes it). Changing the joint's attachments doesn't move the arm.
- A part anchored by the server is pinned even though the player's device owns their character (used for the cage).

## Ghost models (live in Studio, not git)
- Each ghost's AI-generated mesh is in **ServerStorage.GhostMeshes**, named by ghost id (`wisp`, `boo`, … `spectre_king`). A template is a MeshPart or a Model of MeshParts (the Wraith is split into pieces). `ServerStorage.GhostMeshBackups` holds the Wraith's original.
- These are saved with the place, so remind the user to save/publish after changing them. If a mesh is missing, the ghost falls back to a simple ball.
- `GhostModels.<id>` sets size, transparency, glow and particles. Mesh attributes: `Flicker = false` skips the flame stretch; `Walk = true` waddles while unowned. Animated parts carry the `Animated` attribute so StealService leaves their welds alone.
- When generating meshes, keep designs original (no copies of other games' characters) and compare candidates side by side at ground level, then reset the Edit camera.
- Sounds come from the Creator Store; prefer Roblox-licensed audio (APM Music, Pro Sound Effects) or audio made for games over clips ripped from other games, and say so when a pick is from an unknown uploader. Their IDs live in `GameConfig`.

## Testing
- To test Haunted Hour without waiting, set `HauntedHourStart` / `HauntedHourEnd` on ReplicatedStorage from the Server (`workspace:GetServerTimeNow() + seconds`); GhostService and every client read them live. Friend boost can be faked the same way with the `FriendsHere` / `FriendBoost` player attributes.
- Edit config toggles with the Edit tool, not PowerShell `Set-Content -Encoding utf8` (Windows PowerShell 5.1 adds a byte-order mark).
- `GameConfig.StudioTestCashOn` (start with `StudioTestCash`, $1B, never saved) and `GameConfig.StudioBoostSpawns` (equal ghost odds, 2× spawn rate) only apply in Studio. Both are off by default; turn on for testing expensive/rare ghosts, and turn back off before committing.
- Stealing, catching, items hitting someone, lock-with-thief, bidding and anything about what other players see need a 2-player test (Test → Clients and Servers, 2 players); the user starts it. `list_roblox_studios` then shows the server and each player window (find which is which with `game.Players.LocalPlayer.Name`), and `execute_luau` / `user_keyboard_input` / `user_mouse_input` can drive each one. Studio test players have UserIds -1 (Player1) and -2; to test an allow-listed item, add `-1` to its list with a `TEMPORARY` comment and remove it before committing. In Studio solo, the player is the user's own account (jerizaxe, 5783726738).
- DataStore warnings in Studio output are expected (Studio API access is off), and so is the "Infinite yield ... leaderstats" warning they cause. Cash only appears a few seconds after joining, and saving can only be checked in the live game.
- `execute_luau` gets its own copy of every ModuleScript, so requiring a service there gives a fresh, empty copy (no plots, no players). Test like a player instead: move the character (`PivotTo`), press E with `user_keyboard_input` to use a prompt, and read results from the Server or Client. Stateless modules (`GhostModels`, `GhostLabel`) are fine to require for building previews.
- To buy from the walkway: find a ghost in `workspace.WalkwayGhosts` with an enabled `BuyPrompt`, `PivotTo` at `Body.Position + (0, 1, 4)` facing it, and press E straight away (the ghosts keep moving).
- Click GUI buttons with `user_mouse_input` `moveTo` + `instance_path` (e.g. `LocalPlayer.PlayerGui.Sidebar.Root.Index.Holder.IndexButton`); screen coordinates don't reach GUI buttons, so give buttons names.
- Tool calls take seconds, so for timing (how long a cage lasts, when someone lands, whether a player can walk out) arm a script on the client first that waits for the state change and measures, then trigger it and read the result.
- To test UI, fire the existing remote directly from the Server: `game.ReplicatedStorage.Remotes.<Name>:FireAllClients(...)`. Don't require `Shared.Remotes` there; it would create a second Remotes folder.
- `screen_capture` with a camera position doesn't draw particles; to see particles, move the character next to the thing and capture without one. Effects that last about a second need a frozen `Clone()` of the parts (or labels, with transparency reset) to catch in a screenshot. A UIStroke outline is drawn just outside its frame.
- Let the user choose sounds by ear: play the candidates in a playtest from the client (`Sound:Play()` on the character's head, a few seconds apart, music paused, `print` the option number). Sounds played in Edit mode aren't heard.
- A tool round trip takes a few seconds, while a short ghost flight lands in about 10 s: buy far from the buyer's base when testing bidding.
- Live settings that aren't code: Max Players is 8 (Creator Hub → place → Access settings → "Maximum Visitor Count"; Studio's `Players.MaxPlayers` may still show an old value). It must match `PlotCount`.

## Rules
- **Server authoritative.** The client only displays and asks. Every buy/sell/steal/re-buy/collect/hit/claim is validated on the server (ownership, cash, distance/inside-plot, lock state, still in flight, cooldowns, allow-lists). Never trust values sent from a client.
- Things only one player should see (their landmines, their cage's passability, the steal alarm) are drawn on that player's device from a remote or attribute, never as server parts.
- Avoid require loops: GhostService must not require StealService (it uses the `onStealPromptTriggered` hook); StealService must not require CageService (it reads the `Caged` attribute).
- Data changes only through DataService. Never save a profile whose load failed (`canSave = false`).
- Put tunable numbers, asset IDs and allow-lists in `GameConfig`/`GhostConfig`, not inline.
- Studio-only edits (parts built by hand, settings, generated meshes) are not in git — prefer building things in code or saving the place file, and tell the user when something lives only in Studio.
